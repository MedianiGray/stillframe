# OCR 段落还原率基准

蓝图 G7 的验收项写的是「三页中英混排文档段落还原正确率 ≥85%」。这个目录把那个 85% 变成一个能复算的数。

## 怎么跑

```powershell
npm run ocr-bench:pages   # 用 PIL 重新画基准图（需要 Python 3 + Pillow + 微软雅黑）
npm run ocr-bench         # 编译纯模块 → 跑七页识别 → 写 report.json
```

跑一遍约 25 秒（七页 tesseract，`chi_sim+eng` fast 包，和网页端同一套）。

## 它测的是什么

`make-pages.py` 用代码把图和真值一起生成，所以任何机器上跑都是同一组输入。七页覆盖：

| 文件 | 版面 | 用来盯什么 |
| --- | --- | --- |
| `page1-zh.png` | 中文正文三段 | 基线 |
| `page2-mixed.png` | 中英混排 | 中英之间的空格/拼接规则 |
| `page3-list-code.png` | 清单 + 代码块 | 清单不被拆散、代码行不被当正文 |
| `page4-two-column.png` | 双栏，栏距 50px | 切栏能不能救回串行 |
| `page5-two-column-wide.png` | 双栏，栏距 140px | 同上，换一个栏距 |
| `page1-zh-small.png` | page1 缩到 13px 字 | 小字号的掉分程度 |
| `page2-mixed-dark.png` | page2 像素反相 | 深色主题 |

`bench.mjs` 不是直接喂原图，而是复现网页端那条路：`toOcrBlob` 的缩放规则（长边 <1200 放大 2 倍、>2400 缩到 2400）→ 900 宽缩略图上 `detectColumns` → 逐栏裁切（左右各留 2px）→ 识别 → 坐标拼回 → `groupParagraphs`。像素从 PPM 读（Node 没有 PNG 解码器，PPM 是未压缩裸 RGB，十几行就能读；这些 PPM 是派生物，不入库）。

## 两个指标

- **recall（还原率）**：每段真值去 OCR 段里找最长公共子序列（字符级、去空白去标点），取最好的一条，累加除以真值总字数。漏字、错字、一段被切碎都会掉分。
- **purity（纯度）**：反过来算，每个 OCR 段的字有多少来自同一段真值。两段被并成一段时 recall 仍可能满分，但 purity 会直接掉下来——这就是为什么要两个都看。

判定：`recall ≥ 0.85 且 purity ≥ 0.85` 才算过；`exactParagraphs` 另外报整段正确数。

## 当前结果

见 `report.json`（每次跑都会重写）。2026-11-27 那次：还原 **99.6%**、纯度 **99.5%**、整段正确 **30/30**，七页全过。

## 这个基准不覆盖什么

七页都是合成图：字号统一、笔画清晰、没有 JPEG 噪声、没有缩放糊字。它能证明「管线的分栏与聚段逻辑对」，不能证明「任意真实截图都这么高」。真实截图样本（含微信/网页/IDE 混排）还没进来，是下一步该补的。
