# 什么叫做「智慧截图」

先把结论放前面：

> 智慧截图不是能截更多东西，而是**从按下快捷键到手里拿到能用的东西**，中间要用户做的决定更少、重来的次数更少、被没收的权力更少。

微软 Snipping Tool、华为/联想的智慧截屏、QQ 截图模块，功能清单高度重叠：全屏、窗口、矩形、延时、滚动、取字、翻译、录屏、贴图、自动保存。差别不在"有没有"，在**每一层替用户省掉了多少动作**。所以这里不用功能数衡量它，用四个可测的量：

| 量 | 含义 | 观察方式 |
| --- | --- | --- |
| 决策次数 | 一次任务里用户要主动选几次（选模式、选区域、选动作、选保存路径） | 数点击与选择 |
| 首次成功率 | 第一次就拿到想要的结果，不需要重截/重识别的比例 | 连做 20 次同类任务 |
| 到结果时间 | 按键 → 可用产物（文字在剪贴板、图在文档里） | 秒表 |
| 打扰预算 | 弹窗、托盘、被抢走的快捷键、后台常驻 | 一天下来被它打断几次 |

一个工具把功能堆满，但这四个数没降，它只是"功能多的截图工具"，不是智慧截图。

---

## 四层，从"拿得到"到"接得上"

### L0 拿得到：结果必须是确定的

这是地基，也是最不像"智能"的一层：同样的操作，每次都给同样的结果。像素对（DPI 混排时不裁边）、窗口对（被遮挡也抓全）、时机对（延时后目标画面已经稳定）、范围对（滚动截图不把自己拼进去）。

**这一层不许"聪明地降级"**。抓不到就报错说清原因，不能悄悄给一张黑图或半张图——用户拿着错的图去汇报，比拿不到图代价大得多。

现状：全屏 / 窗口 / 矩形 / 3s·5s 延时 / 滚动拼接 / 隐藏自身都通了；多显示器与混合 DPI 仍按单屏假设处理，属于已知缺口。

### L1 看得懂：知道画面里是什么

像素本身没有意义，有意义的是**结构**：这是文字还是图、是正文还是表格、是中英混排还是一屏代码、段落在哪断。系统截图工具之所以"智慧"，是因为它拿到的不只是一张位图，而是带版面信息的图层。

Stillframe 现在只做了文字层：离线 OCR 出原文行结构，再按行距与跨列跳跃归并成段。够用，但只是第一层结构。表格的行列、代码的等宽栅格、聊天窗口的发言归属，都还没有。

判据很简单：**给一段识别结果，人能不能直接粘进文档而不必手动重排**。现在正文可以，表格不行。

### L2 猜得准：在用户开口前给出默认动作

智慧的分水岭在这里。截图之后用户想要的东西，九成落在四件事上：复制文字、翻译、存图、贴到屏幕上。既然九成如此，就不该每次都让用户从 15 个按钮里挑。

但"猜"必须配三条约束，缺一条就变成自作聪明：

1. **有默认，但不是唯一**——默认动作高亮，其余仍在，一次点击就能改。
2. **可撤销**——猜错不产生副作用，不自动发出去、不自动上传、不覆盖已有文件。
3. **说得出理由**——界面上有一句"检测到中英混排正文，已选复制文字"，用户能验证你的判断，而不是面对一个黑箱。

现状：取字进面板即出结果、"复制并收起"、取字直达译屏，已经算半个 L2；缺的是**在动作之前的那句判断**——目前不判断内容性质，也不预选动作。

### L3 接得上：结果要落到用户下一站

截图的终点不是一张 PNG，是"这段文字已经在我正在写的文档里"。所以去向比格式重要：剪贴板、图库、贴图浮层、导出目录、文档里的一次粘贴。

现状：剪贴板、图库、贴图、PNG 导出、长图导出都有；缺的是"截完直接进某个应用/文档"的通道，以及图库的可检索（按 OCR 文本找图）。

## 反面清单：什么样的截图不智慧

这七条是判据，也是本项目自查表：

1. **抢不到热键却装作没事**。注册失败静默，用户按半天没反应，只会以为软件坏了。
2. **猜错不兜底**。自动识别的结果直接当成事实，不给人工修正入口。
3. **替用户做不可撤销的决定**。自动上传、自动发送、自动覆盖。
4. **慢半拍**。按完键等两秒才出选框，智慧感立刻归零。
5. **不可预期**。同一操作这次出 A 下次出 B，用户就不敢用。
6. **把隐私当默认**。截图内容默认外发、默认留云端副本。
7. **假装会**。能力没做完却把按钮摆出来，点了只弹一句"暂不支持"。

## 本轮据此改了什么

不是从概念倒推功能，而是这三处本来就违反上面的判据：

- **热键注册失败静默**（违反反面第 1 条）。桌面壳原来只往日志写一行，GUI 没有控制台，等于没提示。现在注册失败会带「哪组键、哪个模式」上报给界面，顶部出现一条可关闭的提示，并指向替代入口（左侧模式卡、快捷浮窗）。顺带把 `--quick` 时的 Ctrl+Alt+Q 也纳入同一套上报。
- **长图自动滚动会把自己拍进去**（违反 L0 确定性）。滚动期间本窗口压在选区上时，每一帧都带着自己，拼出来的长图中间糊一条。现在滚动前先取自身窗口的屏幕矩形，与选区做重叠判定（留 8px 余量，贴边蹭到不算），确实遮挡才隐藏自己、结束后恢复；结果提示延到窗口恢复后再弹，避免"藏起来的那几秒里弹了用户看不见的 toast"。
- **文档与现实不符**（违反反面第 7 条的反向情形——这里是把已做的事说成没做）。README 的已知限制里还写着"自动滚动尚未实现"，桌面壳也被标为"未编译验证"，实际都已跑通。

## 下一步（按"可以弱但不能没有"的最小入口排）

1. **动作前的判断**：截图完成后算一次内容特征（文字密度、行结构、语言占比、等宽栅格），在结果条上写一句"检测到什么"，并按判断预选动作。判错可一键改，判断句始终可见。
2. **双屏与混合 DPI 的坐标归一**：所有矩形统一到一套物理坐标，选区、窗口、自身窗口、滚动注入点共用，避免"点在副屏却滚到主屏"。
3. **图库按文字检索**：OCR 结果随图入库，支持输关键词找图——这是 L3 里最容易被感知的一条。
4. **表格与代码的结构识别**：先做"能识别出这是表格/代码并给等宽或制表输出"，不做完整表格重建。

验收口径沿用开篇四个量：同类任务连做 20 次，记录决策次数、首次成功率、到结果时间；打扰预算按一天实际被打断次数记。
